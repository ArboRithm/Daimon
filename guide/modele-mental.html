Modèle mental ​

Daimon est un outil, pas un assistant. Votre client IA l'interroge ; Daimon perçoit ou agit, puis répond. Il n'appelle aucun modèle d'IA et n'agit jamais de sa propre initiative.

Les organes ​

OrganeRôleOutilsRéférence
VuePerception visuelle : captures d'un écran, localisation d'un texte (OCR sur l'appareil : Apple Vision sous macOS, OCR de Windows sous Windows), géométrie des écrans, calibrationvue_*Vue
TouchéArbre d'accessibilité d'une fenêtre (accessibilité macOS, UI Automation sous Windows), ou élément situé sous un pointtouche_*Touché

Le panneau ​

Un clic sur l'icône de Daimon ouvre le panneau. Il porte :

  • le curseur de plafond des Mains ;
  • les clients IA, avec un interrupteur par client ;
  • les mises à jour ;
  • le journal d'activité, dont le bouton ouvre le dossier ;
  • le réglage Présence à l'écran, qui active l'Overlay ;
  • Ouvrir le dossier de configuration.

Le panneau de Daimon sous macOS, capturé par Daimon lui-même. Le plafond y est réglé sur L4 (autonomie), d'où le bouton rouge « Désengager l'autonomie L4 ».

Percevoir, puis agir ​

Un échange typique : l'IA regarde (Vue ou Touché), décide, puis agit (Mains), et peut montrer ce qu'elle fait (Overlay). Chaque action des Mains a un niveau, et le plafond que vous fixez refuse tout ce qui le dépasse : voir Plafond et exclusions.

L'Overlay est désactivé par défaut ​

Les outils overlay_* répondent toujours ok, même si aucune fenêtre d'overlay n'est en cours d'exécution : l'ordre est alors abandonné. Activez Présence à l'écran dans le panneau pour voir les repères. Un processus à part, le helper, les dessine ; daimon_doctor dit s'il vit (clé overlay).

Diagnostic ​

daimon_doctor donne en un appel l'état des autorisations, leurs conséquences et le plafond actif.
